## 目标与使用场景

- 已确认：现有风格可以保留，信息呈现和整体布局需要优化，解决堆砌感。
- 默认：优先满足手机上快速了解最新公共状态，其次查看动态，再深入历史与依据；桌面也需舒适使用。
- 结果：用户能快速找到最新收录的内容及其时间、可信边界，并能按需进入动态、历史和数据依据。

## 现状与必须保留的行为

| 功能 | 已核实现状及来源 | 保留要求 |

| 公共状态 | `src/PublicUpdates.tsx` 区分公告、观察、赠送次数、冲突及历史回退。 | 不将历史参考说成当前生效；状态、时间、来源和必要警示与对应内容一起显示。 |

| 历史和统计 | `src/History.tsx`、`src/Stats.tsx` 提供筛选、列表／日历、分享、导出和间隔统计。 | 保留 URL 状态、筛选、计算规则、分享和导出；统计范围与历史搜索仍独立。 |

| 估算 | `src/PublicUpdates.tsx` 明确概率不可可靠估算，并展示回测与旧依据。 | 保留结论和可访问的依据；不得引入未经验证的概率。 |

## 方案：一页分层的观察站

1. **顶部与导航**：保留品牌、时区和刷新；导航指向「最新」「动态」「历史」「数据依据」，让用户可直接跳到目标。手机上控件自然换行，不遮挡内容。
2. **最新状态**：首屏用一个主要区域回答「最新收录了什么、何时、属于公告还是观察」。其余相关记录作为同区次级条目，避免多个同等权重的大卡片。无数据、缓存、过期、冲突与历史回退紧贴相关内容，不能只用颜色表示。将冗长的技术时间细节收进可展开的来源详情，但当前数据是否过期、失败或缓存应直接可见。
3. **Tibo 动态**：默认显示最近 3 条；可展开查看其余已收录内容（上限仍为 12 条），并能收起。每条优先呈现时间、相关性与译文；原文、原帖和回复上下文仍可查看。没有译文时直接显示原文。新动态提醒置于区块标题附近，不受列表展开状态影响。动态总数不足时如实显示，不暗示缺失的帖子。
4. **历史与统计**：将历史查询作为独立主要区块，筛选控件按「搜索与筛选」「视图与操作」分组。间隔统计紧邻历史并作为可展开的独立分析区，默认收起；保留范围选择、图表、数据表及统计说明。分享、导出与列表／日历仍可操作。
5. **数据依据**：把估算结论与来源状态放在同一「数据依据」区域：直接显示「目前无法可靠估算概率」，回测细节、旧估算依据及各来源请求详情按需展开。来源署名与具体资料仍关联呈现，不把多个来源描述成独立验证。
6. **视觉组织**：沿用暖纸色、墨色及克制手绘细节，以标题、留白、细分隔和文字层级建立结构；避免每段文字都形成独立外框。事件时间和状态的对齐优先于装饰。

## 范围与约束

- 仅调整现有单页的信息结构、展示密度与交互层次；不新增账户、服务、接口或数据采集。
- 不改变数据、计算、缓存格式、刷新频率、提醒条件、URL 参数含义或来源链接；保留现有内容及必要警示。
- 重要时效、失败、冲突、数据覆盖限制和不确定性在关联内容处可见；完整技术细节可按需展开。页面锚点调整时应保留既有 `#tibo`、`#history`、`#sources` 等外部链接可达。
- 键盘可展开、收起并访问所有内容；焦点清晰、展开状态可识别；手机无页面级横向溢出，表格和图表可局部滚动。

## 2026-11-18 对照 tibo-reset-live 的补充

对照来源：[tibo-reset-live 项目说明](https://github.com/yurenpai/tibo-reset-live)。以下依据其 README 的文字描述及本站源码；未能打开对方截图或运行其应用，也未在本轮实际查看本站页面，因此不评价视觉细节或宣称实测交互。

- 对方以重置日历为核心，并提供重置动态、28 天计划和全部动态三类视图。本站已有历史日历，但入口埋在筛选工具中。建议在历史标题旁明确展示「列表／日历」切换，让日历成为可发现的主要视图；仍默认列表，避免假设用户更偏好日历。保留未收录不等于未发生、记录类型和时区说明。
- 对方明确区分预告到时、完成帖与社区观察。本站已有公告、观察和历史回退区分，但首屏还可把「记录类型／时间／来源」组成固定阅读顺序，遇到不明确时明确写未知。当前数据不支持时不自行推断预告完成或个人到账。
- 对方将数据来源与后台状态集中，逐项显示成功时间和失败原因。本站已有逐来源详情；建议在来源区域顶端增加简短的总体读取概况，仅根据现有请求与缓存状态得出，逐项失败仍可展开，不把单一成功误称全部正常。关键缓存和失败提示继续留在对应内容附近。
- 对方区分动态视图的方式提示本站需要更好地组织动态；本轮先保留最近 3 条与展开全部的方案，不增加未经现有数据支持的 28 天计划分类。
- 28 天计划、人物阶段、桌面通知、自托管后台及自动到时状态属于对方功能，不纳入本轮；它们涉及新数据、规则或运行方式，不能仅作为布局调整引入。
- 验收补充：历史的列表／日历入口清晰可见；总体来源概况能正确体现部分失败、缓存和无数据，不掩盖具体错误；在缺少明确证据时不出现推断完成或到账的表述。

## 2026-11-18 实际界面对照补充

通过浏览器查看本站线上桌面首屏，以及参考项目的 [重置日历截图](https://github.com/yurenpai/tibo-reset-live/blob/main/docs/images/reset-calendar.png)；参考图是 2026-10-23 演示数据，不代表当前状态。未运行参考应用，也未进行手机真机检查。

- 本站首屏观察：一个大框内有三张形态相近的记录卡，最新条目在标题和第一张卡中重复，多个边框与相近权重占用较多纵向空间。建议最新记录直接成为主内容，其余记录压缩为两行次级记录，取消不必要的嵌套框；每条仍保留时间、状态与对应链接。
- 参考图观察：月历占主要空间，选中日期的记录在右侧集中呈现，时间、说明和来源跟随所选日期。建议本站桌面日历视图采用「左侧月历、右侧所选日期记录」；手机上下排列。未选择日期时显示明确引导或当前筛选结果，不自动制造当天有记录的印象。空日期要可选并明确显示未收录，保留现有筛选及 URL 行为。
- 参考图顶部有大面积主题插画和庆祝文案，视觉识别度强但占据较多空间。本站建议继续采用克制手绘风格，用小型手绘标记和清晰字号形成焦点，不引入可能暗示账户到账的人物状态或庆祝语。
- 参考图用日历格内标签加图例解释类型；本站日历可在空间允许时显示短类型标签，狭窄屏幕保留标记和可访问名称，不能仅靠颜色区分。日期详情需显示事件类型、时间精度、范围、冲突和原帖入口。
- 验收补充：桌面选择某日时日历与当日匹配记录同屏；手机先日历后记录，无页面级横向溢出；选择空日期明确显示未收录，原有搜索、类型、月份、日期和时区筛选及分享链接保持一致。
